API Docs

Everything you can do on the Privo site, you can do from a script. Create and edit short links, read a link back, or check a destination against the safety list — no tracking, ever.

Building an agent or integration? Fetch the OpenAPI spec or the llms.txt version of these docs — both are written to be machine-consumable.

Authentication

Creating a link is free and anonymous — but links you create anonymously can't be edited later. To own your links, create an API key in Privo Cloud → API Keys and send it with every request:

Authorization: Bearer pv_your_key_here

Keys are never displayed and can only be copied immediately after creation or rotation. If one leaks, rotate or revoke it in Privo Cloud — the old key stops working immediately.

Each key is limited to the permissions you pick when creating it:

Scope Allows
links:read Fetch link details on privo.fyi and your verified custom domains.
links:write Create and edit links under privo.fyi.
links:custom Create and edit links on the verified custom domains on your account.

A request outside the key's scopes returns 403. A quick way to test a key:

curl https://privo.fyi/api/me \ -H "Authorization: Bearer pv_your_key_here"

Create a link

POST /api/link

Field What it is
url (required) The destination. Must start with http:// or https://.
shortcode Your own code: 4–45 ASCII letters and digits, case-sensitive, stored verbatim — MyArticle and myarticle are different links. Taken names and reserved page names (about, terms, privacy, stop, report, login, admin, cloud, assets, api, legal, auth, me, docs) return 409.
domain A body field here — unlike read/edit, where it's a query parameter. Defaults to privo.fyi. A custom domain must be verified on your account and the key needs the links:custom scope.
seo Optional object overriding the preview the destination reports. Fields: title (≤200 chars), description (≤1000), siteName (≤100), image (≤2048, must be an http(s) URL). Any field you omit falls back to the destination's own metadata.

For example:

curl https://privo.fyi/api/link \ -X POST \ -H "Authorization: Bearer pv_your_key_here" \ -H "Content-Type: application/json" \ -d '{"url": "https://example.com/article", "shortcode": "myarticle"}'

Which returns 201:

{ "shortcode": "myarticle", // the code used, yours or generated "shortUrl": "https://privo.fyi/myarticle", "originalUrl": "https://example.com/article", "safety": "clean", // "clean" | "flagged" | "unchecked" "preview": { // can be null briefly while metadata is fetched "title": "…", "description": "…", "image": "…", // Privo-hosted copy when available "siteName": "…" } }

Destinations are checked against the admin blocklist and Google Web Risk before a link is stored. A flagged destination returns 422 — with a threats array when Web Risk is the reason:

{ "error": "This URL was flagged by Google Web Risk and can't be shortened.", "threats": ["MALWARE"] } // threats values: MALWARE, SOCIAL_ENGINEERING, UNWANTED_SOFTWARE, BLOCKLIST

POST isn't idempotent — each success creates a new link. But it's safe to retry when you supply a shortcode: a retried conflict returns 409 instead of a duplicate link.

Read a link

GET /api/link/{shortcode}?domain={domain} returns the link's destination, creation date, and preview details. It's public for privo.fyi links — no key needed. For a custom domain, send a key with the links:read or links:custom scope and the domain must be verified on your account. Note domain is a query parameter here, not a body field.

curl https://privo.fyi/api/link/myarticle curl "https://privo.fyi/api/link/go?domain=go.example.com" \ -H "Authorization: Bearer pv_your_key_here"

Which returns:

{ "shortcode": "myarticle", "url": "https://example.com/article", "createdAt": "2026-01-15 10:23:41", // UTC, "YYYY-MM-DD HH:MM:SS" "shortUrl": "https://privo.fyi/myarticle", "preview": { "title": "…", "description": "…", "image": "…", "siteName": "…" } }

There is no endpoint that lists an account's links — the links list lives in the Privo Cloud dashboard and needs a browser session.

Edit a link

GET|PUT /api/cloud/link/{shortcode}?domain={domain} reads or updates a link on your account. The destination is re-checked for safety on every update.

PUT is a full update, not a merge: both url and seo are required — send "seo": {} for no overrides. Any seo field you omit is re-fetched from the new destination's metadata; the previous preview values are not kept. GET and PUT share a response shape:

{ "shortcode": "myarticle", "shortLink": "privo.fyi/myarticle", // no scheme "url": "https://example.com/new-article", "title": "…", "description": "…", "image": "…", "siteName": "…" }
curl "https://privo.fyi/api/cloud/link/myarticle?domain=privo.fyi" \ -X PUT \ -H "Authorization: Bearer pv_your_key_here" \ -H "Content-Type: application/json" \ -d '{"url": "https://example.com/new-article", "seo": {"title": "New title"}}'

Check a destination

GET /api/check?url={url} runs the same safety check used before every redirect — blocklist first, then Web Risk. Public, no key needed.

curl "https://privo.fyi/api/check?url=https%3A%2F%2Fexample.com" # → { "status": "safe", "threats": [] }

Errors

Every failure is JSON with an error message — nothing else to parse:

{ "error": "Invalid URL provided" }
Status Meaning Example body
400 The request itself was wrong — bad URL, bad shortcode, malformed JSON. {"error": "Invalid URL provided"}
401 No valid session or API key was sent. {"error": "Sign in or send an API key."}
403 Valid auth, but not allowed — a scope the key lacks, an unverified domain, an account limit. {"error": "This API key doesn't have permission…"}
404 No link with that shortcode on that domain — or not one you own. {"error": "Not found"}
409 The requested shortcode is taken or a reserved page name. {"error": "Shortcode already taken"}
422 The destination is blocked or flagged by Google Web Risk. A Web Risk flag adds a threats array; a blocklist hit doesn't. {"error": "…", "threats": ["MALWARE"]}

There are no rate limits today — no 429, no Retry-After. Fair use applies and limits may appear later; build with retries anyway.

Stability

The API is unversioned and additive-stable: new fields may appear in responses (ignore what you don't need), but existing fields won't change meaning or be removed without notice. The exact contract lives in openapi.json.

Quickstart

Key → link → edit → check, end to end:

KEY=pv_your_key_here # create one in Privo Cloud → API Keys # verify the key works curl -s https://privo.fyi/api/me -H "Authorization: Bearer $KEY" # create a link curl -s https://privo.fyi/api/link -X POST \ -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \ -d '{"url": "https://example.com/article", "shortcode": "myarticle"}' # read it back (public on privo.fyi — no key needed) curl -s https://privo.fyi/api/link/myarticle # update the destination (seo is required; {} means no overrides) curl -s "https://privo.fyi/api/cloud/link/myarticle?domain=privo.fyi" -X PUT \ -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \ -d '{"url": "https://example.com/new-article", "seo": {}}' # check a URL before linking it curl -s "https://privo.fyi/api/check?url=https%3A%2F%2Fexample.com"

Managing keys

Keys are managed in Privo Cloud, not over the API — so a leaked key can't mint more keys. Up to 20 active keys per account.
