API Docs

Everything you can do on the Privo site, you can do from a script. Create and edit short links, read a link back, or check a destination against the safety list — no tracking, ever.

Authentication

Creating a link is free and anonymous — but links you create anonymously can't be edited later. To own your links, create an API key in Privo Cloud → API Keys and send it with every request:

Authorization: Bearer pv_your_key_here

Keys are shown once at creation. If one leaks, revoke it in Privo Cloud — the old key stops working immediately. A quick way to test a key:

curl https://privo.fyi/api/me \ -H "Authorization: Bearer pv_your_key_here"

Create a link

POST /api/link

Field What it is
url (required) The destination. Must start with http:// or https://.
shortcode Your own code, 4–45 letters and digits. Taken names and page names return 409.
domain Defaults to privo.fyi. A custom domain must be verified on your account (requires a key).
seo Optional object with title, description, siteName, image — overrides the preview the destination reports.

For example:

curl https://privo.fyi/api/link \ -X POST \ -H "Authorization: Bearer pv_your_key_here" \ -H "Content-Type: application/json" \ -d '{"url": "https://example.com/article", "shortcode": "myarticle"}'

Which returns:

{ "shortcode": "myarticle", "shortUrl": "https://privo.fyi/myarticle", "originalUrl": "https://example.com/article", "safety": "safe", "preview": { "title": "…", "description": "…", "image": "…", "siteName": "…" } }

Destinations are checked against the admin blocklist and Google Web Risk before a link is stored. A flagged destination returns 422 with a threats list.

Read a link

GET /api/link/{shortcode} is public — no key needed. It returns the link's destination, creation date, and preview details for privo.fyi links:

curl https://privo.fyi/api/link/myarticle

Edit a link

GET|PUT /api/cloud/link/{shortcode}?domain={domain} reads or updates a link on your account. The destination is re-checked for safety on every update.

curl "https://privo.fyi/api/cloud/link/myarticle?domain=privo.fyi" \ -X PUT \ -H "Authorization: Bearer pv_your_key_here" \ -H "Content-Type: application/json" \ -d '{"url": "https://example.com/new-article", "seo": {"title": "New title"}}'

Check a destination

GET /api/check?url={url} runs the same safety check used before every redirect — blocklist first, then Web Risk. Public, no key needed.

curl "https://privo.fyi/api/check?url=https%3A%2F%2Fexample.com" # → { "status": "safe", "threats": [] }

Errors

Failures return JSON with an error message and one of these statuses:

Status Meaning
400 The request itself was wrong — bad URL, bad shortcode, malformed JSON.
401 No valid session or API key was sent.
403 Valid auth, but not allowed — e.g. an unverified domain or an account limit.
404 / 409 Not found, or the requested shortcode is taken or reserved.
422 The destination is blocked or flagged by Google Web Risk.

Managing keys

Keys are managed in Privo Cloud, not over the API — so a leaked key can't mint more keys. Up to 20 active keys per account.
